# Dot 脸部动画调试

Dot 头像、Settings → Pets 的悬浮宠物和 Windows 的 NatsumePet 程序是不同入口。一个入口的文件或程序版本不能证明其它入口使用相同素材；应分别核对图集内容与 SHA-256。

## 已核对的宿主行为

以下节奏仅是 2026-10-02 检查 Codex 26.928.3736.0 安装版代码所得的历史记录，不代表当前版本行为。宿主使用链式 `setTimeout`，每个延迟回调只推进一帧，再按回调时间安排下一帧；迟到时不会按绝对时间补帧。idle 六帧停留 `[1680, 660, 660, 840, 840, 1920]` ms，循环 6600 ms；work 行 7 六帧停留 `[120, 120, 120, 120, 120, 220]` ms，循环 820 ms。图集本身不能设置 FPS，改 GIF 演示速度也不会提高宿主更新频率。这些数值属于被检查的安装版本，不保证其它版本相同。

Dot 状态选择器只自动使用待机行 0 和工作行 7。通用图集虽然包含其它动作行，Dot 不会因此自动触发这些动作。v2 注视行 9–10 提供十六个静态方向；注视覆盖待机时会暂停待机计时，清除后从 idle 首帧重新等待完整 1680 ms。

10 秒注视 lease 只对应本机 Codex 安装包中已检查的特定网页 Dot 组件及 `dot-mode.mjs` 预览模型，不能外推为 chatgpt.com 当前网页的普遍行为。在该实现中，指针进入头像交互区域时建立 lease；移出区域不会立即取消，租期内全页主非触摸指针移动仍可改变方向，区内移动不会续期。到期时注视取消但保留内部“仍在区域内”状态，所以需先移出再进入才能重新开始。blur 和 document-hidden 的行为也只作为已检查实现的对照；document-hidden 不作为动画全局暂停，普通宿主计时器受浏览器节流，回调恢复后仍逐次推进一帧。

第四轮只读检查的本机安装版为 Codex 26.930.2377.0，安装 bundle SHA-256 `7a65bbbdf265aaa130a6670f1d310e7113646f9b86b2e9602e82fee400a92856`。其中检查的网页 Dot 组件仍有十秒期限与 blur/hidden 取消，没有点击直接取消监听。该安装包内组件不等于已确认的 chatgpt.com 当前网页构建，尚未验证网站实际加载相同代码；不能用桌面 Codex 版本给网站定版。native 悬浮渲染路径从上游点位生成方向并传入 `lookFrame`；它没有使用这条网页期限，点位来源和点击退出需在实际入口另验。不能据此把持续注视定性为图集帧率问题，或宣称点击行为已解释。

## 第三轮真实网页 DOM 转帧采样

2026-10-02 对已有只读 DOM 样本做了保守区间分析。会话工作态采了 120 次，观察跨度约 7.167 秒；可见行始终为 7，49 次转帧都按 F0→F1→F2→F3→F4→F5→F0 顺序，共有 7 个完整周期。基于 RPC 读取前后界限，七周期平均时长范围为 844.3–877.3 ms。单周期区间都包含 820 ms，但合并首尾边界后平均范围高于严格 820 ms；观测与名义帧停留加回调延长相容，不能称为实际周期严格通过 820 ms。读取界限不是精确转帧时间。

外观编辑器待机态采了 240 次、约 10.408 秒，只观察到 1 个完整周期，范围 6547–6731 ms，包含名义 6600 ms。采样组件属于外观编辑器，不能替代会话 idle 验收；这批同步前样本未观察会话 idle。样本记录的是 DOM 帧格，不是屏幕呈现时刻；也未验证加载图集字节与本地素材 SHA 相同，因此不能把这些时序读数绑定到某一特定图集。没有据此推断 paint FPS、精确事件循环迟到或真实 8 小时耐久性。

同步后另采集真实会话头像 idle：840 次 DOM 读取均在 row 0 c0–c5，分成两个各 420 次的连续 burst，request 时间跨度分别为 0–20.396 秒和 36.755–55.539 秒，中间有 16.359 秒未观测空档；两段实际采样跨度合计 39.180 秒。观察到 36 次转帧，全部按 F0→F1→F2→F3→F4→F5→F0 前进；每段有两个完整周期，四个周期的保守区间分别为 6533–6723、6525–6724、6591–6767、6533–6706 ms，均包含名义 6600 ms。两段完整周期平均范围为 6579.0–6673.5 和 6606.5–6692.0 ms。严格固定 6600 ms phase 约束不成立；各帧名义最小驻留加非负回调延长可行，因此这组短时观测与宿主链式计时模型相容，不能称为精确 6600 ms 实测通过，也未发现样本内 DOM 倒序、跳帧或换行问题。

真实会话样本的 CSS 逻辑尺寸为 59.0729×64 px；经过约 1.2235 倍统一布局变换后，DOM bounding rect 为 72.28×78.31 px。二者是变换前后不同层次的读数，不代表角色框尺寸故障。840 次读取覆盖的是 DOM 样式帧格，不是屏幕 paint 时间或 FPS；两个 burst 中间不推断播放行为，也不代表连续 55.5 秒采样、8 小时浏览器运行或 native 耐久测试。

64 px 角色框现有预览布局正确：方形区域中按 192×208 的内在比例缩放，画布约 59.08×64 px，与会话 DOM 样本约 59.07×64 px 一致，不需改默认值或标签。

前三轮待机候选中，前两版因 64 px 下好奇与浅笑层次不清晰而拒绝；candidate3 通过最终结构、编码质量及独立视觉 QA，并已同步。第三轮 revision `2026-10-02-idle-expression-03` 只改 row 0 c0–c5，以物理侧倾配合眼神；微笑保持温和，F2 在 64 px 下可读。当前公开图集为 1536×2288、2,740,570 bytes，SHA-256 `fa6a47edddffc172ebf284cf1fbca27307725485b2c045d829e2f20a3b84c3be`；累计改行仍为 0 和 7。

独立注视复核未发现方向标注错误、象限错误、倒退或必须修复的缺陷。067.5° 与 045° 接近，差异主要集中在 090°；这是正常尺寸审阅后可接受的提醒，不再要求重绘。只有真实使用出现可见问题时才重新评估注视行。

第三轮同步已核验：同一云端条目重新下载的 PNG 与候选、公开、native 和 canonical 图集解码后的 RGBA 逐像素相同，解码 RGBA SHA-256 为 `bbb1dc74087cf17ba551cef5293ac63adc5f9ec37d5da5c753c05898eb3ec8bc`。Fresh browser 核验确认本轮只更新原云端素材，未更改 Dot/Work 的选择。素材一致性不代表真实 Dot 端到端体验；本轮未改宿主 FPS。

## 第五轮自然工作态观察

2026-10-02 在用户已有网页 Dot 会话中，不发送测试消息、不点击或拖动头像，连续采集 360 次 DOM 帧格，采样跨度 18.747 秒。所有样本均为可见、非悬停的 row 7 c0–c5；135 次观察到的转帧按六格循环顺序前进，未见样本内倒序、跳格或换行。21 个完整周期的合并平均保守区间为 829.43–841.57 ms，高于严格 820 ms；这组观测与参考最小驻留加非负回调延长相容，不证明网站使用该参考源码。

采样结束后另一次读取观察到非悬停、可见的 idle row 0 c0。两次观察之间有未采样空档，未捕获 work→idle 的切换边界，不能确定切换首帧、耗时或往返通过。第二段采样开始时，原头像外观按钮已不在当前视图，得到零个样本并停止；页面仍在同一 Dot，不能把视图变化判作宠物故障。

本次资源清单没有提供可绑定实现的脚本内容；尝试导出已观察到的图集资源失败，未取得当前加载图集字节。因此资源路径与既有条目相同，只是路径证据，不能证明本次加载像素已与本地图集核对。DOM 读数仍不代表屏幕 paint FPS、注视退出、后台恢复或长时体验通过。素材、云端条目和选择未因本次采样改变。

## 辅助清单排查

旧辅助 metadata 的 `spritesheetLayout.neutralLookFrame` 曾指向 row 0 col 6；alpha 核对中该格的 `getbbox` 为 `None`，row 0 col 0 则非空。清单备份后已改指 row 0 col 0，并绑定当前 revision `2026-10-02-idle-expression-03` 及 SHA-256 `fa6a47edddffc172ebf284cf1fbca27307725485b2c045d829e2f20a3b84c3be`；旧 validation 报告保留为历史记录。没有证据表明 Dot 运行时会读取这份辅助 metadata，因此不能据此认定它是 Dot 行为问题的根因。v2 普通 idle 首帧兼作 neutral，不应另外占用透明 padding 格；使用伴随清单的导入工具应核对格索引与图集哈希。
